# Entrance Canonical Development Routing

## Behavior changed
- Entrance's canonical development routing skill now scopes AIzeDevelopment lookup to the root-level resident parent instead of the source Entrance instance.
- Updated the live Entrance session state for current `entrance.service` sessions so future routed development work resolves to the existing AIze Development parent before creating a task child.
- Service-control spawn handoff now also honors the canonical development parent for communication sessions with the canonical development routing skill, instead of materializing a child directly under the communication session.
- Communication-session spawn handoff now stops after successfully materializing the routed child session, preventing the same request from also falling through to direct `kernel.spawn`.
- GoalManager child-session requests from communication sessions now resolve the same canonical development parent before creating subgoal sessions, while preserving the source Entrance session as `origin_session_id`.
